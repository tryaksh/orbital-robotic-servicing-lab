# Starting the manuscript: the repository, and a prompt for a fresh session

## The manuscript repository already exists

`D:\orbital-servicing-paper\` is created, is a git repository of its own, and
has one commit. It holds exactly this:

```
D:\orbital-servicing-paper\
  MANUSCRIPT.md      the paper. The one file to review.
  AGENTS.md          how any agent works on it. Read before writing.
  make_numbers.py    generates numbers.json from this repository's evidence
  numbers.json       generated, gitignored -- every figure the paper may quote
  figures/           plots and diagrams, each beside the script that made it
  refs.bib           citations (not yet created)
```

Two Markdown files, deliberately. A manuscript repository accumulates outlines,
notes and session summaries until nobody can tell which file is the paper.
`MANUSCRIPT.md` is always the current state of the paper; as prose replaces
skeleton, the skeleton it replaces is deleted.

It is a separate repository because this one's history is evidence, and mixing
eighty drafts of a paragraph into it makes `git log` useless for the thing it is
for. Keeping them apart also means every number has to be fetched deliberately
rather than half-remembered from a nearby file.

## The rule the prose runs on

No number appears in `MANUSCRIPT.md` unless it is in `numbers.json`, and
`numbers.json` is generated by `make_numbers.py` from `evidence/MANIFEST.json`
here. Retracted and historical reports are excluded by construction, so the
generator cannot emit a withdrawn figure even if a draft asks for one.

This is the same discipline the code runs on, applied to the prose. It is the
cheapest defence against the one failure that would actually sink the paper: a
figure that was true in September and is not in November.

## Markdown first, Overleaf last

Draft in Markdown. Assistants write markedly better prose when they are not also
generating LaTeX environments, and drafts get read more carefully when they are
readable. Frontiers accepts Word and LaTeX; converting a finished Markdown draft
with `pandoc` into their template is an afternoon, and it happens once, at the
end, when the words have stopped moving. Use Overleaf for that final pass only.

## The prompt for a fresh session

Start the session in `D:\6axis-space-robotics` — the drafting agent needs to
read the evidence — and paste everything below.

---

> I want the first draft of the paper this repository is the evidence for. The
> manuscript repository already exists at `D:\orbital-servicing-paper\`.
>
> **Read `D:\orbital-servicing-paper\AGENTS.md` first.** It is short and it
> governs everything you do: the two-file rule, the numbers rule, the prose
> style, and what you must never write. Then read
> `D:\orbital-servicing-paper\MANUSCRIPT.md`, which is a skeleton with the claim
> order settled and every number bound to the file it must be read from.
>
> **Then read, in this order, in this repository:** `docs/paper_position.md` —
> what the paper may and may not claim, and the prior art that forbids the
> obvious framing. It is the most important file and several of its decisions
> would be expensive for you to re-derive; it also carries a correction made the
> day it was written, which matters more than the rest of the file. Then
> `docs/NOW.md` for the measured state with intervals, and
> `docs/seating_controller.md` and `docs/sim_to_real.md`, which are two arguments
> already written out that you should reuse rather than rewrite.
>
> Do not read `evidence/*.json` in bulk. Query `evidence/MANIFEST.json`.
>
> **Before any prose, run `python make_numbers.py` in the manuscript repository**
> and read `numbers.json`. Every figure you write must come from there. If you
> want a number that is not in it, extend the generator rather than typing the
> number.
>
> **Then draft one section at a time and stop after each for review.** Follow the
> section order in `MANUSCRIPT.md`; it is deliberate. Start with the workcell and
> task description, which is the section least likely to change under you, and
> leave the abstract until last.
>
> Some results are still running. Check `docs/NOW.md` for what has landed, and
> write "pending" rather than guessing. In particular: the pooled camera-driven
> chain rate, the training-seed spreads, and whether the seating phase is learned
> or scripted. Never report a training reward as a success rate.
>
> Say what failed. This project's strongest material is negative, and the paper
> is weaker without it.
>
> Start by reading. Show me the section you propose to write first and your
> outline for it before you write a paragraph of prose.

---
